# 借鉴 Project Maya 的系统优化方案与落地记录

本文档记录从 **Project Maya (`mw00/project-maya`)** 调研并采纳至 **myds** 推理引擎的架构与设计优化。

---

## 一、 优化 1：基于物理代价模型的自适应投机解码控制器

### 1.1 问题背景与痛点
在 `myds` 的前期实验（账本 §100/§101）中：
* **PLD（Prompt Lookup Decoding）投机实测 −6.6%（倒亏）**；
* **DSpark 投机实测：最高 11.1% 接受率 × 3.04× 验证成本 ⇒ 净慢**。

**瓶颈根因**：
在 MoE 架构中，验证多 Token 时，各 Token 路由到的专家是**并集关系**，独立专家数 $U(k)$ 会随推测步长 $k$ 迅速膨胀。加之快照状态暂存与回滚的固定开销，推测验证步的相对耗时约为单步解码的 $1.25\sim1.35$ 倍。若草稿接受率 $q$ 较低（如 $q < 0.35$），单步期望产出无法抵消额外开销，投机必定导致端到端吞吐下降。

### 1.2 Maya 的解法与落地实现
参考 Maya 的 `src/spec/controller.cpp`，我们将基于匹配长度的接受率先验与在线指数移动平均（EMA）引入 `include/myds_pld.h` 与 `src/myds_engine.c`：

1. **扩展 PLD 草稿提取**：
   * 增加 `myds_pld_propose_ex`，在检索匹配的同时输出实际命中的 N-gram 长度 `matched_ng`。
2. **N-gram 长度分桶与先验**：
   * 桶 0（$N=2$）：先验接受率 $0.35$
   * 桶 1（$N=3$）：先验接受率 $0.60$
   * 桶 2（$N=4$）：先验接受率 $0.80$
   * 桶 3（$N \ge 5$）：先验接受率 $0.92$
3. **收支平衡门禁（Breakeven Safeguard）**：
   $$\text{Expected Tokens} = 1.0 + q$$
   在相对验证开销约为 $1.28$ 的前提下，只有当该桶的历史估计接受率 $q \ge 0.38$ 时才发起推测 forward；否则直接放弃推测草稿，安全退回原生单步解码。
4. **在线自适应学习**：
   每次验证完成后，根据实际命中结果以 $\alpha = 0.15$ 进行 EMA 平滑更新：
   $$q_{\text{new}} = (1 - \alpha) \cdot q_{\text{old}} + \alpha \cdot \text{hit}$$
   在代码、结构化文本等高频模式下自动加速，在普通文本误匹配时自动关断，彻底消除负收益。

## 二、 优化 2：LoopGuard 服务端周期性死循环检测与自愈

### 2.1 问题背景与痛点
在超低比特量化（Q2_K / IQ2）以及长思维链（`<think>`）生成过程中，大模型在贪婪采样（`temperature=0`）或特定提示词下存在退化为**无限周期死循环**的物理风险（如连续循环输出某一段 4~64 token 的代码、模板或字符），直到打满 `max_new_tokens`，严重浪费 GPU 显存带宽与算力。

### 2.2 Maya 的解法与落地实现
参考 Maya 的 `serve/loop_guard.py`，实现轻量级环形历史检测器 `include/myds_loop_guard.h` 并接入生成流：

1. **滑动窗口周期检测**：
   * 维护容量 1024 的 Token 历史环形缓冲；
   * 针对周期 $P \in [4, 256]$：
     * 短周期（$P < 16$）：检测到连续重复 4 次即判定死循环；
     * 长周期（$P \ge 16$）：检测到连续重复 3 次即判定死循环；
2. **优雅自愈拦截**：
   * 命中死循环后输出警告日志，将停止原因置为 `MYDS_STOP_EOS` 并立即退出生成循环；
3. **环境开关**：
   * 通过 `MYDS_LOOP_GUARD`（`1` 开启，`0` 关闭）控制；HTTP 服务端默认开启保护。

## 三、 优化 3：MoE 专家非对称量化方案（模型侧演进建议）

### 3.1 理论依据
参考 Maya 的 DeepSeek-V4.1 量化配方（`tools/ds4/recipe_maya_s_test.json`）：
* **Down 投影**（`ffn.down`）：维度从 $2048 \to 5120$，负责聚合各特征通道并重构 Residual 流，数值敏感度远高于 Gate/Up；
* **Gate & Up 投影**（`ffn.gate`, `ffn.up`）：仅负责升维与门控筛选，对低比特容忍度极高。

### 3.2 建议的非对称量化规格
* **MoE Gate / Up**：保持 `Q2_K`（或 `IQ2_XXS`）；
* **MoE Down**：提升至 **`Q3_K`**（或 `IQ3_S`）；
* **关键张量保留**：`hc_`、`norm`、`engram`、`attn_sinks` 维持 `Q8_0` 或 FP8。

### 3.3 M2 Ultra 192GB 显存预算评估
* 40 层 MoE 共有 $40 \times 384 = 15360$ 个专家；
* 单个专家的 Down 投影大小约为 10.5 MB（Q2） $\to$ 14.5 MB（Q3），单个专家增量仅 ~4 MB；
* 384 个专家全量驻留增加约 $15360 \times 4\text{ MB} \approx 61.4\text{ GB}$；
* 若采用仅将高频热层/热专家升级为 Q3_K，或在 192GB 统一内存中精细排布，即可在完全常驻的前提下显著降低困惑度损失（提升 Top-1 预测一致率）。
